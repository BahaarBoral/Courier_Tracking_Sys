# Live Demonstration Script (12-15 Minutes)

## Prerequisites
- Oracle database running locally.
- DB initialized with all SQL scripts (`01_tables.sql` to `10_sample_data.sql`).
- Node.js backend running (`cd backend && npm start`).
- Browser open to `http://localhost:3000`.
- Oracle SQL Developer open with an active connection to the project schema.

---

## Demo Flow

### Part 1: Customer Experience (3 minutes)

**Step 1: Landing Page (0:00 - 0:30)**
- Open browser to `http://localhost:3000`.
- Point out the responsive UI and professional layout.
- Click on **"Login"**.

**Step 2: Customer Login (0:30 - 1:30)**
- Enter credentials: `customer.demo@example.com` / `Demo@123`.
- Show the Customer Dashboard.
- **Talking Point:** *"These live statistics are populated using our Oracle views and PL/SQL functions to ensure optimal performance."*

**Step 3: Book Shipment (1:30 - 3:00)**
- Navigate to **"Book Shipment"**.
- Fill out form (Destination, Weight, Type).
- Click Submit.
- Show the success modal and note the generated Tracking ID.
- Navigate to **"Tracking"**, enter the ID, and show the initial status.

### Part 2: Oracle Verification (2 minutes)

**Step 1: Verify Booking (3:00 - 4:00)**
- Open Oracle SQL Developer.
- Run query: `SELECT * FROM SHIPMENT ORDER BY Booking_Date DESC;`
- Point out the newly inserted row.

**Step 2: Trigger Demonstration (4:00 - 5:00)**
- Run query: `SELECT * FROM AUDIT_LOG ORDER BY Action_Date DESC;`
- **Talking Point:** *"Notice this log entry. This was automatically generated by an Oracle AFTER INSERT Trigger when the shipment was created, demonstrating Active Database concepts."*

### Part 3: Warehouse Operations (2 minutes)

**Step 1: Warehouse Dashboard (5:00 - 6:00)**
- Log out of customer account.
- Log in as Warehouse Staff: `staff1@example.com` / `Staff@123`.
- View the pending shipments list.

**Step 2: Assign Agent (6:00 - 7:00)**
- Select the newly created shipment.
- Assign it to an available Delivery Agent.
- **Talking Point:** *"This action fires a PL/SQL procedure that checks warehouse capacity and agent availability atomically."*

### Part 4: Delivery Agent Workflow (2 minutes)

**Step 1: Update Status (7:00 - 9:00)**
- Log in as Delivery Agent: `agent1@example.com` / `Agent@123`.
- Show the assigned shipment.
- Update status to "OUT_FOR_DELIVERY", then "DELIVERED".
- Switch back to SQL Developer and query the `TRACKING` table to show history progression.

### Part 5: Admin Dashboard & Reports (2 minutes)

**Step 1: Admin Insights (9:00 - 11:00)**
- Log in as Admin: `admin@example.com` / `Admin@123`.
- Show the reporting charts (Revenue, Shipments by Status).
- **Talking Point:** *"This dashboard aggregates data using complex JOINs and GROUP BY clauses encapsulated in our database views."*

### Part 6: Database Concepts Demo (3 minutes)

**Step 1: EXPLAIN PLAN (11:00 - 12:00)**
- In SQL Developer, execute:
  ```sql
  EXPLAIN PLAN FOR SELECT * FROM ACCOUNT WHERE Email = 'customer.demo@example.com';
  SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);
  ```
- **Talking Point:** *"We can see the optimizer is using the unique index on the Email column rather than a full table scan, showing physical database optimization."*

**Step 2: Transactions and Rollback (12:00 - 14:00)**
- Demonstrate a transaction rollback. Try to manually insert a shipment with a non-existent `Customer_ID`.
- Result: Foreign Key constraint violation.
- **Talking Point:** *"Because of the ACID properties and PL/SQL exception handling, the partial transaction is fully rolled back using the ROLLBACK TO SAVEPOINT command, leaving no orphan records."*

### Part 7: Concurrency Demo (1 minute)

**Step 1: Row Locking (14:00 - 15:00)**
- Open *two separate* SQL Developer connection tabs (Session A and Session B).
- In Session A, run: 
  ```sql
  SELECT * FROM SHIPMENT WHERE Shipment_ID = 1001 FOR UPDATE;
  ```
- In Session B, run an `UPDATE` on the same `Shipment_ID`.
- Show that Session B hangs (blocks) waiting for Session A to `COMMIT` or `ROLLBACK`.
- **Talking Point:** *"This demonstrates concurrency control. Oracle is using row-level locking to ensure serialization and prevent lost updates."*
- Commit Session A, showing Session B instantly complete. 

**End of Demo**
